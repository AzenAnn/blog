    从 C 到 C++ 第一讲精讲¶

    这节课你真正要掌握的核心

    1. C++ 不是“换个语法的 C”，而是“保留 C 的性能，同时增强抽象能力”的语言。
    2. cin、cout、cerr 本质上都是对象，<<、>> 本质上是针对流对象重载过的运算符。
    3. namespace 是为了解决名字冲突，std::cout 里的 std:: 必须理解。
    4. 引用 的本质是“别名”，最重要的用途是参数传递和返回已有对象。
    5. 指针和引用的区别，不只是写法不同，而是语义不同。

    学习地图¶

    模块 你要会什么 重要度
    C++ 历史与定位 知道 C++ 为什么出现，和 C 的关系是什么 高
    Hello World 会写最基本的 C++ 程序，认得 iostream、std::cout、endl 高
    IO 流 理解 cin/cout/cerr 是对象，理解 << >> 为何能链式调用 很高
    命名空间 理解 std、::、using 的含义和使用场景 很高
    引用 vs 指针 分清语义、用法、适用场景、常见错误 最高
    返回引用与内存模型 能判断“返回引用”是否合法，理解栈帧和悬垂引用 很高

    1. C++ 为什么会出现¶

    一句话结论

    C++ 的目标不是取代 C 的性能优势，而是在此基础上提供更强的抽象能力和更好的大型程序组织能力。

    本质解释¶

    C 语言非常强，尤其强在两点：

    1. 性能高
    2. 接近底层，控制力强

    但 C 也有明显问题：

    1. 对复杂程序的抽象能力不够强
    2. 大型项目中，代码组织、复用、维护都比较吃力
    3. 名字冲突、接口管理、数据封装都不够自然

    于是 Bjarne Stroustrup 把 Simula 67 的“类、面向对象”思想引入 C，最早形成了 C with Classes，后来发展为 C++。

    这部分你该记住什么¶

    • C++ 吸收了 C 的效率、灵活性和哲学。
    • C++ 进一步提供了类、封装、继承、多态等能力。
    • 课程后面会不断回到这条主线：从“面向过程”慢慢走向“面向对象”和“抽象建模”。

    时间线你不用死背，但要知道¶

    版本 你要知道的意义
    C++98 第一个标准化版本
    C++11 现代 C++ 的关键转折点
    C++14/17/20 持续增强语言与标准库能力

    学习态度

    历史不是为了背年份，而是为了回答一个更重要的问题：为什么 C++ 会长成今天这样。

    2. 第一个 C++ 程序：你看到的每个符号都要认识¶

    #include <iostream>

int main() {
    std::cout << "hello world c++!" << '\n';
    return 0;
}

    一句话结论

    这段程序表面简单，但已经包含了 C++ 的三个核心特征：标准库、命名空间、流式 IO。

    每一行到底在干什么¶

    代码 作用
    #include <iostream> 引入输入输出流库
    int main() 程序入口
    std::cout 标准输出流对象
    << 向输出流“插入”内容
    '\n' 换行
    return 0; 正常结束程序

    你要特别注意的点¶

    • C++ 常见源文件后缀是 .cpp 或 .cc。
    • 入门时一般用 g++ 编译 C++ 程序。
    • cout 不是函数，它是对象。
    • << 在这里不是位移运算，而是“输出运算”的重载形式。

    更严谨一点

    课件里说“编译工具是 g++ 不是 gcc”，入门这样记没问题。更准确地说，通常我们用 g++ 来编译和链接 C++ 程序，因为它会更自然地按 C++ 方式处理标准库链接。

    '\n' 和 std::endl 的区别¶

    写法 作用
    '\n' 只换行
    std::endl 换行并立即刷新缓冲区

    工程习惯

    不要把 std::endl 当普通换行乱用。大多数时候优先用 '\n'，只有你确实需要立刻刷新输出时再用 std::endl。

    3. IO 流与对象：这是这节课的第一个真正重点¶

    一句话结论

    cin、cout、cerr 之所以“像会说话一样”，是因为它们是对象，而 <<、>> 被重载成了对这些对象进行输入输出的运算符。

    先建立正确直觉¶

    在 C 里你更熟悉的是：

    printf("%d\n", x);
scanf("%d", &x);

    在 C++ 里更典型的是：

    int x;
std::cin >> x;
std::cout << x << '\n';

    这不是“只是换了个写法”，而是设计思想变了：

    • C 更偏“函数 + 格式串”
    • C++ 更偏“对象 + 运算符重载 + 类型安全”

    三个你必须认识的对象¶

    对象 作用
    std::cin 标准输入
    std::cout 标准输出
    std::cerr 标准错误输出

    为什么可以写成链式调用¶

    int a;
double b;
char c;

std::cin >> a >> b >> c;
std::cout << a << ' ' << b << ' ' << c << '\n';

    因为：

    • operator>> 返回输入流本身的引用
    • operator<< 返回输出流本身的引用

    ==所以表达式会变成“处理一次后，继续拿这个流对象往后接”。==

    这件事本质上在考你什么¶

    它在考你是否开始理解 C++ 的两个核心机制：

    1. 对象
    2. 运算符重载

    也就是说，你不能只记“能这么写”，你得知道“为什么能这么写”。

    4. IO 格式控制：会用基本操纵符¶

    常见无参操纵符¶

    操纵符 作用
    std::endl 换行并刷新
    std::dec 十进制
    std::hex 十六进制
    std::oct 八进制
    std::left 左对齐
    std::right 右对齐
    std::fixed 浮点数按定点格式输出
    std::scientific 科学计数法输出
    std::showpoint 总是显示小数点
    std::showpos 非负数显示 +

    常见有参操纵符¶

    需要头文件：

    #include <iomanip>

    常见的有：

    操纵符 作用
    std::setw(n) 设置下一个输出项的宽度
    std::setprecision(n) 设置精度

    典型格式化例子¶

    #include <iostream>
#include <iomanip>

int main() {
    double myFloat = 123.4578;
    int myInt = 5;

    std::cout << std::fixed << std::showpoint << std::setprecision(3);
    std::cout << std::setw(10) << std::left << "Float";
    std::cout << std::setw(12) << std::right << myFloat << '\n';
    std::cout << std::setw(10) << std::left << "Int";
    std::cout << std::setw(12) << std::right << myInt << '\n';
}

    这部分最容易错的地方¶

    • setw(n) 通常只对下一个输出项生效。
    • fixed、setprecision 这类格式设置往往会持续生效。
    • endl 不只是换行，还会刷新缓冲区。
    • cin >> 字符串 遇到空白会停，不会读整行。

    5. 命名空间：为了解决“名字冲突”¶

    一句话结论

    namespace 的本质就是“给名字分组，避免重名冲突”。

    为什么需要命名空间¶

    在 C 里，项目一大，就容易出现“我也叫这个名字，你也叫这个名字”。

    例如：

    • 你写了一个 print
    • 别人也写了一个 print
    • 标准库还可能有类似命名

    这时名字冲突就会让程序很难组织。

    C++ 的解决方案就是：把名字放进不同作用域里。

    基本语法¶

    namespace sysu {
    int x = 10;
}

    使用时：

    std::cout << sysu::x << '\n';

    这里的 :: 叫做作用域解析运算符。

    两种常见使用方式¶

    方式 写法 说明
    有限定名 std::cout 明确写出属于哪个命名空间
    using 指令 using namespace std; 把某个命名空间里的名字整体引入当前作用域
    using 声明 using std::cout; 只引入某一个名字

    课件中的关键例子你必须看懂¶

    #include <iostream>
using namespace std;

int main() {
    const char* cout = "hello world c++!";
    std::cout << cout << endl;
}

    这段代码在说明：

    • 局部变量也可以叫 cout
    • 局部变量会隐藏外层同名名字
    • 但你仍然可以通过 std::cout 明确访问标准库里的输出流对象

    工程建议¶

    推荐习惯

    在小练习里写 using namespace std; 可以。 在正式工程代码里，尤其是头文件里，尽量少用它。 更推荐写成 std::cout、std::string 这种明确形式。

    6. 引用：这节课最重要的核心¶

    一句话结论

    引用可以先把它理解成“已存在对象的别名”，它最重要的价值是让你在不显式写指针解引用的情况下，直接操作原对象。

    最基本定义¶

    int a = 1024;
int& x = a;

    这里：

    • a 是原变量
    • x 是 a 的引用
    • x 不是 a 的拷贝
    • x 改了，a 也会变，因为它们本质上指向同一个对象

    和指针放在一起看最清楚¶

    int a = 1024;
int* p = &a;
int& x = a;

x = 2000;   // 改的是 a
*p = 3000;  // 改的也是 a

    引用和指针的本质区别¶

    比较项 引用 T& 指针 T*
    本质语义 别名 保存地址
    是否必须初始化 必须 不必须
    是否可为空 语义上不应为空 可以为 nullptr
    是否可改绑到别处 不可以 可以
    使用时是否需要解引用 不需要 需要 *
    是否能做指针运算 不行 可以
    适合表达什么 “一定存在的对象别名” “可能为空、可改指向的地址”

    非常重要

    入门时请牢牢记住一句话：引用更像“对象的另一个名字”，指针更像“存着地址的变量”。

    什么时候优先用引用¶

    • 函数参数要求“必须传入一个对象”
    • 函数内部要直接修改外部对象
    • 你不想让调用者写 * 和 &
    • 你想表达“这里不能为空”

    什么时候必须用指针¶

    • 需要表达“可能没有对象”，也就是可空语义
    • 需要在不同对象之间改指向
    • 需要和数组、动态内存、底层接口打交道
    • 需要显式表示地址概念

    7. 值传递、引用传递、指针传递：必须彻底分清¶

    1. 值传递¶

    void swap_value(int x, int y) {
    int temp = x;
    x = y;
    y = temp;
}

    结论：

    • 改的是形参副本
    • 实参本身不会变

    2. 引用传递¶

    void swap_ref(int& x, int& y) {
    int temp = x;
    x = y;
    y = temp;
}

    结论：

    • x、y 是实参的别名
    • 改 x、y 就是在改原变量

    3. 指针传递¶

    void swap_ptr(int* p1, int* p2) {
    int temp = *p1;
    *p1 = *p2;
    *p2 = temp;
}

    调用时：

    int a = 5, b = 9;
swap_ptr(&a, &b);

    结论：

    • 传进去的是地址
    • 函数里要通过解引用 *p1、*p2 才能访问原变量

    三者最关键的区别¶

    方式 传进去的是什么 能不能改实参
    值传递 值的副本 不能
    引用传递 实参的别名 能
    指针传递 实参地址 能

    写代码时的判断方法

    如果你看到函数参数是 T&，第一反应就应该是：这个函数可能会直接操作调用者传进来的对象。

    8. 返回值为什么也可能用引用¶

    课件在讲什么¶

    课件给了两类函数：

    第一类，普通返回值：

    double f(double x) {
    double y = sin(x);
    return y;
}

    第二类，返回引用：

    double& f(double x) {
    static double y;
    y = sin(x);
    return y;
}

    你真正要掌握的不是“这样写更快”，而是“什么时候合法”¶

    一句话结论

    只有当被返回的对象在函数返回后仍然活着时，返回引用才是合法的。

    合法的情况¶

    • 返回全局对象的引用
    • 返回 static 局部变量的引用
    • 返回某个对象成员的引用
    • 返回传入对象本身的引用

    非法且危险的情况¶

    double& bad(double x) {
    double y = sin(x);
    return y;   // 错误：返回局部变量引用
}

    因为：

    • y 是局部自动变量
    • 它在函数结束时就销毁了
    • 返回后这个引用就悬空了
    • 继续使用就是未定义行为

    9. 为什么“不能返回局部变量的引用”：栈帧与内存模型¶

    一句话结论

    局部变量通常放在当前函数的栈帧里，函数一返回，这个栈帧就失效了。

    课件给你的内存模型直觉¶

    概念上可以这样理解：

    代码区（正文段）    存放程序指令
数据区              存放全局变量、静态变量
堆                  动态分配的内存
栈                  函数参数、局部自动变量

    你真正该怎么理解¶

    • 每调用一次函数，通常会创建一个新的栈帧
    • 形参、局部变量大多在这个栈帧中
    • 函数返回后，这个栈帧就结束了
    • 所以局部变量的生命周期也结束了

    这就是为什么下面的代码危险：

    int& bad() {
    int x = 10;
    return x;
}

    这和指针有什么关系¶

    一样危险：

    int* bad_ptr() {
    int x = 10;
    return &x;
}

    引用悬空和指针悬空，本质上都是：你访问了一个已经失效的对象。

    更现代的结论

    不要为了“减少拷贝”就随便返回引用。现代 C++ 有返回值优化（RVO/NRVO）、移动语义等机制，很多时候直接返回值既安全又高效。

    10. 关于“引用不是对象”的正确理解¶

    严谨校正

    课件里把引用讲成“不是对象、不占存储”，这是入门时常见说法。你可以先这么理解，但要知道更严谨的版本。

    入门层面你这样记最稳¶

    • 引用的语义是别名
    • 它必须绑定到某个对象
    • 不能像普通变量那样“先声明后再绑定”
    • 不能把它当普通对象一样随意操作

    更严谨一点¶

    • 在语言语义上，引用不是独立对象
    • 但在编译器实现层面，引用可能通过地址来实现
    • 所以“语义上像别名”比“物理上到底占不占字节”更重要

    入门阶段你暂时不要钻牛角尖的点¶

    • “引用的引用”在直接声明里不成立
    • 但模板推导里有“引用折叠”这种更高级机制
    • 这节课先不展开，先把基本引用吃透更重要

    11. 课件里提到但没展开，你现在就该知道的 const¶

    最基本结论¶

    • const 表示“这个对象通过当前名字不可修改”
    • 在 C++ 里它比 C 更严格

    一个你必须会判断的例子¶

    const char* p = "hello";

    这是对的。

    char* p = "hello";

    这是不推荐甚至会报错的写法。

    为什么¶

    字符串字面量在 C++ 中应看作只读内容，所以应该用：

    • const char*
    • 或者更现代的 std::string

    顺手补一个 constexpr¶

    关键字 含义
    const 只读
    constexpr 编译期常量表达式

    你现在只要先会这句：

    const 强调“不可改”，constexpr 强调“编译期可确定”。

    13. 高频误区¶

    这些错很常见

    • 把引用理解成“语法糖版指针”，但没理解它表达的是“别名语义”
    • 认为返回引用总比返回值快
    • 认为 endl 只是换行
    • 认为 using namespace std; 到处都应该写
    • 认为 char* p = "hello"; 在现代 C++ 里是正常写法
    • 只记 << 是输出，不理解它其实是运算符重载
    • 只会背“引用比指针安全”，但说不出为什么
